# Tasks: Admin session (login + MFA from Next, BFF token strategy)

> Design sanity check: `design.md` was read in full before this breakdown. It is complete (Technical Approach → ADR-1..10 → Data Flow → File Changes for all 5 slices → Interfaces/Contracts → Env handling → Testing Strategy → Threat Matrix → Migration/Rollout → Open Questions) and internally consistent; no truncation found, no edit made.
>
> One noted discrepancy, not a design defect: `proposal.md` and `specs/admin-session/spec.md` both say the route-protection file is `middleware.ts`. `design.md` ADR-3 overrides this to `src/proxy.ts`, with verifiable evidence quoted from the installed `next@16.3.6` docs (`middleware` is deprecated and renamed to `proxy` in v16.0.0). The behavioral contract (cookie-presence check, redirect rules, scenarios) is identical; only the filename changes. Following the spec's literal filename would ship a deprecated, possibly non-functional API on the installed Next version, so tasks below implement `src/proxy.ts` per the design's verified ADR. This is flagged in the Risks section for `sdd-verify` to confirm against the running Next version, not silently resolved.
